# 建築設計知識庫

這個資料夾存放人工整理的 RAG 種子資料。另會讀取 `output/rag/imports/` 中已完成匯入的文件；不掃描整個專案，也不讀取 `api_keys.json`、`.env` 或開發工具設定。本 README 不會進入索引。

現有內容是依目前程式整理的設計知識摘要及註明來源的案例摘要，不是完整法規庫。新增來源前確認內容與目前程式適用範圍，避免把舊版開發紀錄中的已撤回做法當成規則。

每個檔案格式：

```markdown
---
id: unique-document-id
title: 文件標題
source: 書名頁碼、原始網址或專案檔案路徑
updated: "2026-09-17"
scopes: [townhouse, graph]
---
## 主題
可查證的設計內容、適用範圍與限制。
```

- `id` 必須唯一。`updated` 用引號包住，避免被當成日期物件。
- `scopes` 可用 `parse`（需求術語）、`townhouse`（透天選配）、`graph`（房間關係圖）。
- 案例不要放 `parse`：解析需求時不能把案例房數、尺寸拿來補使用者沒講的內容。
- 每節盡量簡短；系統以標題分段，長段按 320 字元切割、重疊 40 字元。
- 放入／修改／移除文件後，下次檢索會按內容指紋自動更新索引；也可執行 `python -m src.knowledge index`。
- PDF、DWG／DXF 與圖片可透過網頁「匯入參考資料」或 `python -m src.knowledge import "檔案或資料夾"` 擷取文字及標註。請核對 OCR 結果；此功能不會還原牆線、房間邊界或比例尺。
- 不要放入 API key、密碼或與設計無關的個資。向量在本機計算，但命中的參考段落會隨既有請求送給 Gemini。

安裝、模型與檢索原理見 `docs/RAG.md`。
