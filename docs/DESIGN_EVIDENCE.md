# 設計證據與人工核對（2026-10-07）

本次補強讓「需求 → 配置 → 幾何檢查 → 人工核對」留下可查閱紀錄。這些功能不等於已完成使用者研究，也不證明 LLM 比傳統方式更有效。

## 網站操作

1. 輸入住宅需求與通行碼，生成初稿。左側「設計證據與人工回饋」可下載 HTML 或 JSON；HTML 可用瀏覽器列印成 PDF。
2. 報告保存原始／本次需求、解析欄位、必要與偏好核對、實際房間面積、配置引擎與退回原因、種子、現有檢查結果、RAG 紀錄，以及完整 BuildingSpec 幾何快照。程式來源指紋及快照 SHA-256 可辨識使用哪一份證據，不是第三方簽章。
3. 在「調整方案」修改需求，新方案記錄父方案、原始需求及實際欄位差異。父方案以伺服器保存的資料為準，不信任瀏覽器自行提供的舊需求。
4. 展開「人工接受或退回初稿」，填入核對者／代號、結果和具體理由，按保存。每筆意見綁定方案快照；重試同一筆送出不會重複新增，並發寫入以鎖與原子檔案替換保護。
5. 「匯入參考資料 → RAG 狀態與檢索驗證」可以檢查模型、段數與維度，也可獨立查詢。這個查詢不會呼叫生成模型；只有生成報告中的 sent_chunk_ids 表示實際附加到提示的段落。

失敗候選若有結構化診斷（422／502／503）會提供未交付報告 JSON，不能對上一張成功圖面誤記回饋。一般輸入格式錯誤仍顯示原有錯誤訊息，不生成報告。舊方案缺少的欄位標成未記錄，不反推或補造理由。報告只保存程式原有路徑及候選紀錄，不記錄或編造模型內部思考。

人工接受僅代表對初稿的意見，不會自動加入 RAG。要把方案變成案例，仍需另行核對原圖、適用尺寸與限制。使用同一通行碼的人共享核對權限；這不是獨立使用者身分認證。

Render 免費部署的檔案儲存仍是暫存；請下載圖面及報告備份。模型隨容器建置保存，不代表使用者匯入資料或回饋可跨重新部署保留。

## 向量與檢索證據

部署使用固定版本 intfloat/multilingual-e5-small 的官方 int8 ONNX 模型；下載檔案先驗證 SHA-256。向量為 384 維，attention-mask 平均池化後做 L2 正規化，query/passage 使用不同前綴，最多 512 tokens。它表達文字語意，沒有把某一維定義成房間長寬或座標；幾何仍由配置及檢查程式處理。

每筆檢索紀錄保存查詢、模型／後端簽名、320 字元切段與 40 字元重疊、0.84 初始門檻、排序候選及去除原因。候選紀錄最多 20 筆，candidate_total 說明實際候選總數；不是完整索引匯出。selected 為檢索選中，context_budget 為提示長度限制而未送出，sent_chunk_ids 才是實際送出的段落。引用不證明模型採用，也不表示參考資料已被專業核實。

ONNX int8 與原本 Torch 浮點模型具有不同的簽名，索引會重建；量化可能改變相似度排序，仍需標註檢索集校準。兩個真實模型煙霧案例：車庫／玄關步行動線取得相關段落（0.851821、0.843579）；連棟透天中段採光／天井取得相關段落（最高 0.905408）。這只是功能驗證，不是檢索準確率或 LLM 效益評估。

## 固定驗證案例

```powershell
.venv\Scripts\python.exe scripts/verify_fixed_cases.py --output output/verification
```

輸出 fixed_cases.json 與 fixed_cases.html。固定 seed=7、建築尺寸 4.5×14 米，涵蓋：三房、四房、三房加一樓車位、一層容量不足、房數不符、刪除一樓所有門、家具穿牆、刻意重疊房間、缺少尺寸檢查報告、必要需求未滿足時阻擋交付。預期結果固定在腳本中；不以當次輸出反推通過條件。

本次 10/10 通過。重疊案例檢查的是 LayoutValidator 的重疊偵測，明確不是宣稱所有產線已將它納入最終交付關卡。這組小型案例也不能代表所有基地、建築類型、耐震或法規檢查已完整。

## 仍需真人完成

問題定義與人工流程見 PROBLEM_DEFINITION.md。使用 DESIGN_WORKFLOW_CASE_TEMPLATE.md 訪談／觀察真實人工案例，留下來源、需求、判斷及修改原因；功能測試不替代這項研究。系統產出配置初稿，尚不提供完整施工或建照設計。

雲端首次載入發現分詞器記憶體負擔，因此改用同一官方 SentencePiece 檔，以 XLM-R 特殊 token 對齊方式編碼，簽名升級 v2 並重建索引。已比對中文、日文、英文、emoji、空白、特殊 token 與長文本截斷等 9 個樣例的編碼；這些樣例不能代表任意 Unicode 皆完全一致。對齊依據見 [Hugging Face XLM-R 原始碼](https://github.com/huggingface/transformers/blob/v4.44.2/src/transformers/models/xlm_roberta/tokenization_xlm_roberta.py)。
