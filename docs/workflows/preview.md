# 出圖,而且自己要看過

> ⚠️ 這是**工作流程**,不是 API 文件。數字(尺寸區間、常數)的唯一出處一律是
> 程式碼本身;這裡寫的是「怎麼做、會踩到什麼」。

使用者驗收的方式是**看圖**,不是看測試數字。測試全綠不代表圖好看、不代表房間配得合理。
這支的重點不是「產生檔案」,是**你自己要用 Read 打開那張 PNG 看過**再跟使用者講結論。

## 怎麼跑

```bash
python scripts/preview_plan.py --width 6 --depth 12 --bedrooms 3 --floors 3
python scripts/preview_plan.py --width 15 --depth 15 --out output/preview/big
python scripts/preview_plan.py --width 6 --depth 12 --seed 7      # 換格局變體
python scripts/preview_plan.py --width 6 --depth 12 --sheet       # 含 A3 圖框
```

- 尺寸單位**公尺**,一律當**建築物**尺寸(`setback=0`),跟 `scan_plans.py` 同一套慣例。
- 輸出:`output/preview/` 下每層一張 PNG(1F/2F/…、多層再加剖面/立面)+ plan_check 報告。
- 退出碼:全合格 0,有硬錯誤 1。
- `--lineweight` 預設 6(牆不糊成一團、標註字看得清楚)。benchmark 縮圖用的 20
  在這個尺寸會把牆畫成黑塊、蓋掉門窗編號,**不要用**。

## 流程

1. **挑會打到你改動的尺寸**,不要每次都畫 6×12。改哪條骨架就畫哪條的區間
   (對照 [CLAUDE.md](../../AGENTS.md) 的骨架路由表),改共用元件(門洞/樓梯導牆/家具)
   就四條各畫一張。
2. 跑腳本 → **`Read` 打開每張 PNG 實際看**。
3. 看完再回報。看圖時至少確認:
   - 房間有沒有門、門會不會開在牆角或階梯上
   - 家具有沒有穿牆、有沒有畫到房間外
   - 樓梯兩側有沒有牆、起步平台在不在
   - 標註讀不讀得出來(門窗編號 D1/W1、牆厚引線、剖切符號 A—A、`UP 16`)
   - 多層的話:樓梯/管道間上下層有沒有對齊
4. **把 PNG 路徑給使用者**,讓他自己也看得到。

## 判讀

- plan_check 說「全過」但圖看起來怪 → 那是**規則還沒涵蓋的缺口**,值得回報,
  可能就是下一條該加的硬規則(用 `/newrule`)。
- 只跑一組尺寸不算驗收。系統性錯誤要靠 `/scan` 掃一輪,兩支是互補的:
  **`/scan` 抓「有沒有錯」,`/preview` 抓「錯之外還有沒有醜」**。

## 坑

- `preview.py`(舊的)是寫死 `hello_cad.dxf` 的一次性腳本,**不是**這支,別叫錯。
- 骨架種類沒有記在 spec 上(`ai_extra` 是 web 層回應的 dict,不是 spec 欄位),
  腳本不會告訴你走了哪條產線 —— 要確認就對照骨架路由表的尺寸區間。
