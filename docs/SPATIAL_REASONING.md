# 房間、動線與指定房數：操作及計算依據

更新日期：2026-09-23。這次補上三項能力：可點選的房間關係圖、逐房檢查證據與衝突定位、窄透天既有區塊的指定臥室數分配。產出定位為可檢查的住宅配置初稿。

## 操作

1. 在網站輸入「透天三層，建築物 4.5×14 米，三房」並生成。
2. 先看左側需求核對的「要求」與「實際」是否相符。
3. 按「房間與動線分析」，選樓層、點房間，可查看尺寸、門窗、家具、從本層起點的連通路徑，以及相關問題。
4. 勾選「顯示僅相鄰的關係」，可分辨共用邊界與真正可通行的連接。
5. 「下載分析紀錄」輸出本次分析 JSON，保存座標、房間編號、連線、量測與衝突。
6. 在「調整方案」輸入「改成四房」。必要房數由實際房間重新計算；沒有提到的必要條件保留。

失敗時顯示本次診斷，不產生本次成功圖面。若畫布仍留著上次成功方案，錯誤訊息會明示。歷史方案若沒有保存分析資料，須重新生成才能查看。

## 三項功能如何計算

### 房間與動線圖

輸入是最終 BuildingSpec / FloorPlanSpec，不是模型撰寫的說明。每個房間以樓層索引與房間索引識別，例如 f1:r0；同名房間不共用識別碼。

重用 connectivity.build_graphs：多邊形共用邊界達 MIN_SHARE 才建立相鄰關係；共用邊界有門，或扣除牆後的開放通道達 MIN_PASSAGE，才建立可通行關係。窗戶不視為通道。門洞包含沒有門扇物件的開放口。

一樓以實際外牆門洞所接的房間為起點，上層以樓梯投影相交的樓梯間為起點。從起點做廣度優先搜尋（BFS），保存抵達各房間的節點序列；找不到起點則標為未驗證。天井、管道間不當成一般可進入房間。

圖上的線是房間之間的拓撲關係，不是人實際走過的軌跡。BFS 的路徑是最少連接步數，不是最短公尺距離，也不驗證跨樓層逃生。

### 逐房檢查與衝突說明

面積以房間多邊形計算，座標單位為毫米；面積是牆中心線範圍，不是淨使用面積。外接矩形尺寸也不等於房間淨寬。門窗取自實際牆上開口，家具取自碰撞引擎的物件外框。

房內可通行性另呼叫既有 room_circulation 模型，使用原本通行寬門檻、牆與家具障礙物及服務目標。此結果和「房間間有沒有連線」分開呈現。

plan_check、code_check 與需求核對的問題保留原始代碼、嚴重度與量測敘述。能唯一對應房間時直接定位；原始檢查只記名稱而遇到同名房間時，標示所有候選，明示無法唯一定位。只有樓層／全棟位置的問題不捏造房間座標。改善建議是固定規則文字，並非模型推測。

報告產生失敗會回報未驗證；既有必要條件、圖面與尺寸規則仍是成功出圖前的關卡。沒有被報告列為問題，不等於完整設計審查通過。

### 指定全棟臥室數

僅針對「必要且等於指定數量」的臥室要求啟用。先產生原有窄透天骨架；保留一樓公共／車庫層的功能及樓梯核跨層對齊，計算上層既有臥室、主臥和書房區塊的初篩容量。

容量初篩使用 ROOM_PROGRAM 的臥室面積與尺寸規則。先保留一間可用主臥，再優先分配到目前臥室較少的樓層，同數量時選較低樓層。各層先選主臥、既有臥室，再選可用書房。

接著在建立牆、門窗與家具之前套用房間用途：被選書房改為臥室，剩餘臥室改為彈性起居，再走原有門窗、家具、退讓修復與檢查流程。自動選型與退讓仍可能調整核心位置或區塊，並非鎖死上一張圖的座標。容量紀錄是重建前的初篩，不是重建後最大可行房數。最終再次數實際 bedroom / master_bedroom，孝親房不混入臥室數。

容量不足會保留原需求，列出各層目前候選容量。此容量只是本骨架候選的限制，不是「這塊基地在所有設計方法下都不可能」的證明。

## 與 RAG、LLM 的分工

RAG 已接入既有流程。本機 multilingual-e5-small 將查詢與來源段落編成 384 維、L2 正規化的語意向量，以餘弦相似度排序；先依用途與已知適用條件篩選。向量的每一維不是房數、座標或法規變數。

LLM 負責需求解析與配置提案，RAG 提供有出處的文字參考。房間區塊分配、幾何落實、家具、門洞、圖論分析與檢核由 Python 程式執行。檢索到相關文章，不代表幾何成立；匯入 PDF／DWG／圖片取得的文字，也不等於還原了平面幾何。

## 本次實作範圍

- 房數分配是既有窄透天骨架的用途分配，尚不會為了指定房數任意切牆、合併房間或搬動樓梯核。
- 一樓保留公共功能，因此單層透天的三房要求會回報目前容量不足。
- 淺基地、寬基地與其他骨架仍由原有能力生成，再以必要條件把關；不能宣稱所有尺寸都支援任意房數。
- 「至少／至多」及偏好仍由原本生成與最終核對處理，沒有套用精確房數配置。
- 若書房等其他必要條件與房數配置衝突，最後核對仍會阻擋；尚未建立全域多需求約束求解器。
- 低階 generate_narrow_building 的舊 bedrooms 參數保留相容行為；精確總數使用新增 bedroom_target。網頁已傳入必要需求。

## 程式位置與重現

| 功能 | 檔案 |
|---|---|
| 房數分配 | src/design/bedroom_program.py |
| 骨架重建入口 | src/design/layout/narrow_house.py |
| 幾何分析報告 | src/design/spatial_report.py |

| 回歸測試 | tests/test_spatial_reasoning.py |
| 隨機尺寸與房數掃描 | scripts/scan_bedroom_program.py |

在專案根目錄執行：

```powershell
.venv\Scripts\python.exe -m pytest tests/test_spatial_reasoning.py -q
.venv\Scripts\python.exe scripts/scan_bedroom_program.py --n 80 --seed 0 --json output/bedroom_scan.json
```

掃描將成功、容量不足、檢核失敗、其他例外分開統計；容量不足不算成功圖面。完整測試與此次實測結論見隨附驗證紀錄。
