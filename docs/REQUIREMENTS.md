# 需求核對與 RAG 補強

完成日期：2026-09-22。修改已整合回桌面 `專題/structural_cad`，本機網頁為 http://127.0.0.1:8014/。

這次把重點放在「需求不能被偷改、結果必須能核對」。系統定位是住宅配置初稿工具；通過目前的程式檢查，不等同完整施工設計或建照審查。

## 已補上的功能

1. **必要條件與偏好分開保存。** 一般明確要求視為必要；寫「最好有天井」「天井可取消」才視為偏好。保留原句，修改時保護未提到的欄位。對「四房」等明確數量另做文字核對，留下解析校正紀錄。
2. **必要條件不隨重試取消。** 透天選配的樓層、房數、車庫、天井會鎖定必要值。選項放不下時回報原因；可退讓偏好仍可以調整。
3. **從實際圖面核對。** 清點樓層、臥室、車輛配置、車庫、書房、孝親房、天井，顯示要求值、實際值、原句及對應房間。沒有完成量測的條件標為「未驗證」。
4. **檢查沒有完成就停止出圖。** 缺報告、格式不一致、檢查程式拋出例外，都不算通過。圖面錯誤、已實作尺寸規則不符、必要需求不符也會擋下。錯誤回應保留可核對資料，不產生新的下載檔。
5. **先選可行候選，再比較分數。** 有需求契約的 AI 流程先以必要需求與現有檢查是否通過排序，再比較原有評分。修正提示仍帶原始條件；網頁可查看配置調整紀錄。
6. **RAG 先做條件篩選。** 新增案例尺寸基準、寬深範圍、樓層、臥室、車位、共壁、開窗側、限制與核對狀態。已知不相容者先排除，再用原本 E5 的 384 維語意向量排序。未知條件不偽裝成已核對適用。
7. **評分對應實際圖面。** 新產生方案直接保存該配置的評分；不再把 AI 的需求交給規則引擎重畫，再用另一張圖的分數代表它。

## 怎麼使用

輸入範例：

> 透天三層，建築物 4.5×14 米，四房，最好有天井。

一般「三房」按實際三間臥室核對；「至少三房」才允許超過三間。樓層按明確指定數量核對。可用寬深按建築軸線外框不得超出輸入尺寸檢查，不代表精確覆蓋基地、退縮或建蔽率已完成審查。

產生結果後看「需求核對」：

| 狀態 | 意義 |
|---|---|
| 滿足 | 實際配置符合該項目前實作的量測方式 |
| 未滿足 | 實際數量或條件與要求不符 |
| 未驗證 | 現有表示或檢查不足，不能當成已滿足 |

必要項目的後兩種狀態不會被當成完成方案。偏好未滿足則保留在報告裡，可以交付其他必要項目已通過的初稿。

如果本次生成失敗，畫布可能仍保留前次成功方案；錯誤提示會明確說明，不代表本次生成成功。

## 整理 RAG 案例

在「匯入參考資料 → 核對參考資料與適用條件」按「載入資料清單」。

- 依原始圖面／文字填寬深、樓層等範圍。固定值的上下限填同一個數字。
- 不知道的條件留空。網頁標題寫「5 米」不代表已確認所有案例都適用 5 米基地。
- 區分基地尺寸與建築尺寸；兩種基準不同時，不直接混用數值排除。
- 開窗側使用 N 北、S 南、E 東、W 西，例如 `N,S`。
- 標示「已人工核對」須填核對者與依據，例如圖號、頁碼、原文段落。系統不會替你假裝已核對。
- 儲存後更新索引；若索引尚未就緒，會把「已儲存」與「可檢索」分開回報。

透天選配會帶建築可用寬深、共壁及前後開窗條件；樓層／房數／車位沿用本案解析值。排除原因、適用條件不足與來源核對狀態保存在引用報告。原本的 PDF、DWG、DXF、圖片及網頁文字匯入仍可使用；匯入並不等於還原幾何。

## 檢查範圍與尚存限制

- 窄透天骨架尚不能按任意房數、地下室條件自由重組。以前「要求三房卻畫四房」「要求地下室卻沒畫」可能被當成成功，現在會被擋下。這次沒有把它改造成通用約束求解器。
- 臥室依房間用途計數；另指定的一樓孝親房分開核對。車位依圖面汽車配置計數，尚不驗證車輛轉彎軌跡。
- 方位以房間形心與樓層外框的相對位置近似核對。沒有可靠表示的項目會回報未驗證，例如目前共用核對器中的集合住宅每排戶數。
- 自然語言仍可能誤讀；新增的文字核對只涵蓋明確常見數量與條件，不代表完整理解任何中文需求。
- RAG 相似度不是可信度；沒有條件的資料可以作一般參考，但不會被宣稱已驗證適用。
- 採光、通風與尺寸檢查仍有簡化假設；沒有新增正式法規認證或物理模擬。
